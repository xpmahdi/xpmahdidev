Philosophy & Approach

Why "The Normal One"?

In an industry cluttered with buzzword overload and fragile, over-engineered architectures, I prioritize the bedrock: clean database fundamentals, predictable code, and reproducible system environments.

Relational Integrity First

Fancy models fail if the data warehouse is full of duplicates and orphaned rows. I focus heavily on normalized relational schemas (3NF), constraints, and index profiling.

DataOps & Reproducibility

Eliminating "it worked on my machine". Pipelines are fully containerized with Docker, automated with GitHub Actions, and backed by isolated volumes for persistent storage.

Metrics-Driven Observability

A pipeline isn't complete without telemetry. Real-time metric scraping with Prometheus and visual Grafana dashboards ensure query bottlenecks and connection spikes are caught early.

# pipeline.py - Sample Python Data Ingestion Worker
import psycopg2
from psycopg2.extras import execute_batch
import requests

def ingest_media_records(api_endpoint: str, db_config: dict):
    """Fetches raw JSON, normalizes attributes, and batch UPSERTs into PostgreSQL."""
    response = requests.get(api_endpoint, timeout=10)
    response.raise_for_status()
    raw_records = response.json()

    clean_data = [
        (item['id'], item['title'].strip(), item.get('release_year'), item.get('rating', 0.0))
        for item in raw_records if 'id' in item and 'title' in item
    ]

    upsert_query = """
    INSERT INTO media_catalog (id, title, release_year, rating)
    VALUES (%s, %s, %s, %s)
    ON CONFLICT (id) DO UPDATE SET
        rating = EXCLUDED.rating,
        updated_at = NOW();
    """

    with psycopg2.connect(**db_config) as conn:
        with conn.cursor() as cur:
            execute_batch(cur, upsert_query, clean_data, page_size=200)
    print(f"✅ Ingestion complete: {len(clean_data)} rows committed.")
